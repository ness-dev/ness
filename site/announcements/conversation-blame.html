Ask any line why it’s there

Ness can now keep track of which agent turn wrote every line of your code. Open a file, hover a line, and you get the conversation and the prompt behind it. Then you can go ask that conversation what it was thinking.

Y Upvote on Hacker News

git blame, but for conversations

Most of the code I ship these days was typed by an agent. That has made git blame a lot less useful. It tells me the line came from “me”, in a commit called something like “Fix uploads”, and the actual reasoning lives in some chat transcript I closed three weeks ago. When I find a weird line, the question I really want to ask is “why did you do this?”, and until now there was nobody to ask.

So now when history tracking is on for a repo, Ness records which Claude Code turn wrote each line. Here’s what that looks like in the file viewer:

  • A bar in the gutter. Every line gets a thin bar, coloured by the turn that wrote it. Dashed bars are older history, backfilled from your existing transcripts and commits, so it’s useful on day one and not just for new work.
  • Hover for the story. The card shows the session, which turn it was and when it ended, the prompt that started the conversation, and the prompt for that turn. Click the bar to pin it.
  • Ask it why. Hit Ask this conversation on the pinned card (or right-click the line) and Ness forks the conversation that wrote it into a new Chat tab, already asking about that line. The original session is left alone. As of this turn forks from the moment the line was written instead, so the agent answers without knowing what happened afterwards.

Lines are matched by content, not by commit, so squashing and rebasing doesn’t lose the trail.

Powered by loch

The recording is done by loch, a small CLI for saving and moving agent coding sessions around. If you read the chat forking post, this is the tool that started life in a forked chat. loch hooks into Claude Code and records each turn locally as it ends. Ness reads that back to draw the gutter, and uses loch to fork the conversation when you ask a line about itself.

Everything stays on your machine. Turning it on adds loch’s hooks to each worktree’s .claude/settings.local.json, snapshots live in ~/.loch, and nothing is uploaded. If you don’t have loch installed (or the one on your PATH is older), Ness downloads a pinned, checksum-verified copy into ~/.loch/bin.

Turning it on

  • New to Ness: the setup step that installs the status hooks now has a “Keep track of which agent made every change” checkbox, ticked by default. Every repo you add after that starts recording automatically.
  • Already using Ness: you’ll see an Install history tracking prompt in the sidebar for each repo. Click it for a quick explainer and a one-click install, or hit the X if you don’t want it for that repo.
  • Either way: Settings → Conversation blame has the gutter toggle, the list of repos being recorded, and whether new repos should record automatically.

In conclusion, and what’s next

This is just the beginning of what loch can do. In a recent post I made about loch I called out that I believe in the near future we will be sharing our agent conversations with each other. The work we do as software engineers is no longer the code we produce but the conversations, insight and attention that we give to agents. We’ll worry less and less about the code itself. When I review a peer’s pull request, I care a lot more about what they said to the agent while building it than I do about the literal code they’re showing me they made. If I have feedback on the change, I should say it directly to the agent, not to the person who made the change (who will then just say it to their agent).

If you are excited and interested in working on this problem, come join me on the Slack or the GitHub repo. I would love to chat about the future we are building towards.

– Mike
